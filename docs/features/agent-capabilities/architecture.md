# 目标架构

## 当前架构证据

- [docsagent/agent/application.py:41] 由 `App` 集中管理设置、会话、任务、模型、上下文和工具调用，是本次拆分运行职责的入口。
- [docsagent/agent/loop.py:24] 已有有界模型/工具循环、重复调用检测、输出和上下文预算，可作为运行时控制循环的基础。
- [docsagent/agent/tools/dispatcher.py:9] 分组 Schema 描述模型工具，集中分发器检查项目范围、文档意图和审批；MCP 工具以命名空间动态加入。
- [docsagent/providers/model_client.py:14] 已通过一个客户端适配多种模型请求格式，但没有能力协商、多模态输入或流式任务接口。
- [docsagent/agent/sessions.py:10] 会话历史保存在用户级 SQLite；任务事件历史单独保存，进程重启后不恢复模型/工具循环。
- [docsagent/agent/prompts.py:3] 当前运行指令允许项目文件编辑与检查命令，同时要求 Git 提交和外部副作用经过确认。
- [docsagent/agent/workflows/documents.py:27] 文档流程已有任务规划、草稿、精确补丁、校验和提案审核，可以继续作为文档专精工作流。

## 约束

- 产品是单用户、本地项目 Agent；会话与事件历史落在权限受限的用户数据目录，凭据与附件分离存储。
- Agent 可在项目当前工作区修改文件；任务开始记录 Git 状态和文件版本，任务内版本变化时拒绝覆盖。
- 项目范围、命令、浏览器、MCP 和远程模型数据传输各自有明确授权；Git 提交和外部副作用必须确认。
- 文件内容、网页、模型输出和 MCP 元数据都是不可信数据，不得覆盖运行时策略。
- Office/PDF 首版提取文本，音频转写依赖可选语音模型；没有视觉模型时图像、扫描件 OCR 和视频画面分析显式失败。动态子 Agent 和不可信 Skill 代码执行不在范围内。

## 备选方案

- 保持 `App` 与一个大型分发器，继续将能力堆进现有模块：短期改动少，但审批、传输和任务状态会相互耦合。
- 采用单一运行时核心、明确端口和适配器：新增能力独立实现，可按策略注册，测试和替换成本较低；模块边界需要一次小规模整理。
- 首版引入 Manager/Worker 多 Agent：并发能力更强，但会增加协调、共享工作区冲突、成本与故障归因复杂度，目前没有评测证据支持。

## 目标架构

- 现有 `AgentLoop` 负责有界模型/工具循环、预算、事件、取消和验证闭环；任务事件会落盘供后续查询，进程重启不续跑。
- `tools/schemas.py` 按任务组维护模型可见的 JSON Schema；`ToolDispatcher` 是唯一执行入口，按工具类别执行项目范围、任务意图和审批检查。MCP 工具在本轮按服务器命名空间动态加入。
- 项目文件、Shell、网页搜索、浏览器、MCP、附件解析器均实现独立适配器。MCP 支持 `stdio` 和 Streamable HTTP；服务器逐个启用，工具名带服务器命名空间，工具定义按需加载。
- `ContextBuilder` 汇总有来源的项目/网页/附件证据、会话历史、用户确认约束和当前任务状态。项目检索使用代码符号索引与本地全文检索；是否增加向量检索由标注评测决定。
- 本地 SQLite 保存会话和任务事件历史；进程重启后不恢复正在运行的模型/工具循环。长期记忆通过独立 opt-in 存储，带来源和时间，并提供查看和删除。
- `ModelAdapter` 对外声明文本、工具、流式、图片、音频等能力；不支持的模态明确拒绝，不静默转成不等价请求。
- 文档工作流按“证据 → 缺口/大纲 → 草稿 → 结构与来源校验 → Diff”执行；当前不运行独立模型审稿器。
- 代码工作流按“基线 → 计划 → 编辑 → 授权检查 → 回读/测试 → Diff 审核 → 用户确认提交”执行。已配置的项目测试、Lint、构建命令可运行；其他 Shell 命令逐次审批。
- Web/API 保留现有任务启动与事件流，并提供任务历史查询/删除、审批和取消操作。事件带任务 ID、序号、阶段和结构化结果。

## 取舍与风险

- 单 Agent 加固定工作流、确定性验证和文档评审，首版能够覆盖完整闭环；仅在任务评测证明并行执行有收益后增加子 Agent。
- 当前工作区直接编辑符合用户审核 Diff 的流程，但并非文件系统沙箱。项目命令仍以当前系统用户权限运行；未配置检查命令和更高风险操作须逐次确认。
- 浏览器使用隔离配置，不读取系统浏览器资料；用户可在隔离环境中自行登录。网页和 MCP 返回作为数据处理，不能影响授权策略。
- PDF/Office 在本地提取；音频依赖可选转写模型。当前图像视觉、OCR 和视频画面能力未接入，工具必须显式报错；不可将空提取结果当成分析结论。
- 本地持久化会增加隐私和磁盘生命周期责任；清空会话、删除任务和清理附件必须由用户可见、可验证地完成。

## 假设与待确认

- 默认模型供应商和网页搜索后端可配置；每个后端通过适配器接入，不将单一供应商 API 暴露给运行时。
- 多模态支持指输入理解、提取和分析，不包括媒体创作。
- 当前工作副本没有 `.git` 元数据，无法填写真实 Base commit；在真实 Git checkout 中补入基线并审核后，才能按项目约定提交文档包及后续代码。
